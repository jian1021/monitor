# Meteora Meme 代币筛选与反弹监控方案

## 1. 项目目标

在现有 Python 监控项目中增加一套 **Solana / Meteora Meme 代币筛选与反弹候选提醒系统**。

核心思路：

1. **筛选代币基本属性**，排除明显低流动性、低活跃度和风险异常的池子。
2. 对通过筛选的代币监控 **1 小时 RSI < 10**。
3. 观察 **5 分钟 K 线是否出现止跌、反弹迹象**。
4. 通过飞书发送提醒，由本人决定是否买入、评估单边 LP 或放弃交易。

监控系统只负责筛选和提醒，不自动下单。

## 2. 整体流程

```text
Meteora / Solana 池子数据
        ↓
第一层：代币基本属性筛选
        ↓
第二层：1H RSI < 10
        ↓
第三层：5m 止跌 / 反弹信号
        ↓
飞书发送提醒
        ↓
人工判断与交易
```

## 3. 第一层：代币基本属性筛选

这是整个系统的第一步，优先级高于 RSI。

### 3.1 流动性 / TVL

* 过滤 TVL 过低的池子。
* 关注流动性是否突然大幅下降。
* 避免仅因 TVL 较高就认定代币安全。

配置项：

* `MIN_POOL_TVL_USD`：最低池子 TVL。

### 3.2 成交量与活跃度

* 检查 24 小时成交量是否达到最低要求。
* 观察成交是否持续，避免被单次异常成交误导。
* 可辅助计算成交量与 TVL 的比值。

配置项：

* `MIN_VOLUME_24H_USD`：最低 24 小时成交量。
* `MIN_VOLUME_TVL_RATIO`：最低成交量 / TVL 比值。
* `MIN_RECENT_TRADES`：近期最低交易笔数，前提是数据源可靠。

### 3.3 市值与数据完整性

* 记录市值、流通市值或 FDV（如果数据可靠）。
* 排除价格异常、代币地址不匹配、关键数据缺失的池子。
* 市值仅用于辅助筛选，不代表代币安全。

配置项：

* `MIN_MARKET_CAP_USD`：最低市值，可选。

### 3.4 代币与池子风险

在数据源支持的情况下，检查：

* 是否存在可疑的冻结、增发或权限控制。
* 持币集中度是否异常。
* 池子流动性是否突然下降。
* 交易是否过度集中或存在异常成交。
* 池子和代币地址是否正确匹配。

无法获取的信息标记为“未知”，不能默认视为安全。

### 3.5 第一层筛选结果

每个池子输出以下状态：

* `PASS`：通过，进入 RSI 监控。
* `REJECT`：触发明确排除条件。
* `REVIEW`：数据不足或风险无法判断，暂不进入自动候选名单。

## 4. 第二层：1 小时 RSI 超跌筛选

仅对第一层通过的代币计算 RSI。

触发条件：

```python
RSI_1H < 10
```

触发后：

* 加入超跌候选名单。
* 记录代币地址、池子地址、价格、RSI 和触发时间。
* 进入 5 分钟 K 线观察阶段。
* 设置重复提醒抑制，避免持续低 RSI 导致消息刷屏。

**注意：RSI < 10 只是超跌条件，不代表价格一定反弹。**

## 5. 第三层：5 分钟止跌与反弹信号

初期使用简单、可回测的规则。

### 初始判断规则

1. 最近连续 3–6 根 5 分钟 K 线不再持续创出新低。
2. 随后某根 K 线收盘价突破此前 3–6 根 K 线的局部高点。
3. 如果突破时成交量高于近期均量，可作为额外确认条件。

满足条件后，发送“可能出现反弹确认”的飞书提醒。

这些规则属于待验证的交易假设，可能出现假突破，需要通过历史数据回测。

## 6. 人工交易决策

| 市场状态                 | 处理方式           |
| -------------------- | -------------- |
| 基本属性通过，但 RSI 未达标     | 不进入超跌候选名单      |
| RSI < 10，但 5m 尚未止跌   | 继续观察           |
| 5m 出现止跌与突破信号         | 人工复核后，考虑小额现货交易 |
| 价格处于预设下方买入区域，且愿意持有代币 | 单独评估下方单边 LP    |
| 流动性骤降、风险异常或数据不可信     | 放弃交易           |

### 单边 LP 的风险说明

下方单边 LP 不等于风险对冲。

* 价格继续下跌时，可能不断买入并累积亏损。
* 价格直接反弹时，价格可能未触及挂单区域，导致错过涨幅。
* LP 应作为独立的交易选择，不应自动替代现货买入判断。

## 7. 接入现有 Python 项目

优先在现有 `monitor` 项目上增量开发，复用已经运行的飞书 Webhook。

建议模块划分：

```text
data_sources.py       # 获取池子、价格和成交量
token_filter.py       # 基本属性与风险筛选
indicators.py         # RSI 和 5m K 线信号
candidate_store.py    # 候选名单与提醒状态
feishu_alert.py       # 飞书消息推送
config.py             # 阈值与开关配置
```

具体模块名称应根据现有项目结构调整，不必为了符合示例而大规模重构。

### 候选数据记录

每个候选至少记录：

* 链、代币地址、池子地址。
* TVL、24 小时成交量、成交量 / TVL。
* 市值（如数据可靠）。
* 风险检查结果及未知字段。
* 1H RSI、触发时间和当时价格。
* 5m 止跌与突破状态。
* 提醒时间。
* 信号触发后 15 分钟、1 小时、4 小时的价格表现。

## 8. 开发顺序

1. 确认池子数据来源及字段质量。
2. 实现代币基本属性筛选。
3. 接入 1H RSI < 10 候选识别。
4. 增加 5m 止跌与突破信号。
5. 接入飞书提醒、去重和冷却机制。
6. 记录信号后的价格表现，进行回测。
7. 根据实际数据调整筛选阈值和交易规则。

## 9. 核心原则

* **先筛代币基本属性，再看 RSI。**
* 先排除明显不适合的池子，再寻找超跌机会。
* 阈值配置化，具体数值根据数据与回测确定。
* 不确定的安全信息标记为未知。
* 先做监控和提醒，不自动交易。
* LP 费率只作辅助信息，不作为主要入场依据。
* 所有筛选都无法保证代币不会归零。
