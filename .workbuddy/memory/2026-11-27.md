- 修复 81b3c6a：

    输出与运行环境 TZ 无关。

    6 个展示时间的页面全部改走它（值拷贝 import 在 Cloud 热更新后拿旧函数，

  * **刻意不改** meteora_scanner 的 `alerts.ts` 去重时间戳：它按 SQL 字符串比较

## 修复 LP 区间宽度 HTTP 400「Invalid currency」22:05
- 用户报错：页面分析 Robinhood Chain 的 TSLA/SPCX 池子失败，接口返回
  `{"title":"Invalid currency. Allowed values: usd, token"}`。根因是上一轮把
  `cli --currency` 默认 usd→quote（池子比价）后，`GeckoClient.ohlcv_page` 把
  **内部口径名** quote 原样塞进 API 的 currency 参数——GeckoTerminal 并不接受它，
  于是所有池子的 K 线都取不到（回测的 load_backtest_series 同样受影响）。
- 实测确认（真实 API，Solana MONER0/SOL 与 Robinhood v4 TSLA/SPY 均验证）：
  * `currency=usd&token=base` → close = base_token_price_usd（美元价）
  * `currency=token&token=base` → close = **base_token_price_quote_token**（池子比价，1 base = X quote）✅
  * `currency=token&token=quote` → 倒数比价；`currency=quote` → HTTP 400
- 修复 ca2df00：`data.to_api_currency(currency, token)` 只在 **GeckoClient.ohlcv_page
  发请求时**把 quote → `("token", token)`；上层 CLI 默认值、缓存 series key
  `quote:base`、测试 FakeClient 的 quote 判断全部保持不变（否则 5 个离线测试会错位）。
  cli/backtest/README 同步更正口径说明；新增 tests/test_lprange_currency.py 5 例。
- 验证：全量 400 passed（+5）；真实 API 拿到 40 根比价 K 线（close≈0.0261）；
  页面完整调用链 run_one 对 Robinhood v4 池子成功（2 次请求，仅样本不足警告）；
  模拟「sys.modules 里是旧 data 模块」，_reload_lprange_if_changed() 守卫可自愈
  （_LPR_MODULES 含 lprange.data 且 cli 在其后 reload，cli.GeckoClient 拿到新类）；
  AppTest 冒烟 OK。GCE pull+restart active、无异常。
- **经验**：GeckoTerminal OHLCV 的 `currency` 合法值只有 usd / token；「池子比价」
  是 currency=token + token=base。内部口径名与 API 参数名必须在请求层隔离，
  改 CLI 默认值时务必用真实 API 验证参数被接受，别只看本地离线测试。
